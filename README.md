# Тихий город — игра для изучения ПДД

Браузерная игра на TypeScript, React и Phaser: свободная поездка, разбор дорожной ситуации и повтор. Первая версия работает без бэкенда, история сохраняется в IndexedDB.

Текущая версия — **0.2.0-preview.1**, предпросмотр пяти групп правил. [Описание версии и ограничения](docs/VERSION-0.2.0-preview.1.md) · [Руководство игрока](docs/PLAYER_GUIDE.md) · [Техническая документация](docs/IMPLEMENTATION.md).

## Разработка 0.3.0-preview.1

В ветке `feat/0.3.0-preview.1` продолжается расширение игры. По умолчанию открывается карта четырёх кварталов с плавной камерой. Добавлены базовый поток и обработка столкновений. Это ещё не выпуск всего набора возможностей: новые правила приоритета, встречная полоса и общая приёмка находятся в работе. Опубликованная основа в `main` остаётся `0.2.0-preview.1`.

Схема, дорожные связи и таблицы путей — в [описании города](docs/implementation/0.3.0/CITY.md). Проверка новой карты: `npm run test:e2e:city`. Все браузерные проверки запускаются командой `npm run test:e2e`. Прежние 20 сценариев отдельно запускаются через `npm run test:e2e:legacy` на старой карте через `VITE_LEGACY_MAP=1`; это техническая фикстура для регрессии, а не отдельный игровой режим. Для ручной проверки старой карты: `VITE_LEGACY_MAP=1 npm run dev`.

Базовое поведение машин и его ограничения — в [описании потока](docs/implementation/0.3.0/TRAFFIC.md). Остановка при контакте и выбор места возврата — в [описании столкновений](docs/implementation/0.3.0/COLLISIONS.md).

## Запуск

Нужен Node.js 22.12+ (рекомендуется Node 22, см. `.nvmrc`).

```sh
# Если проект ещё не скачан (нужен доступ к приватному репозиторию):
git clone https://github.com/AlimovaKatrin/pdd.git
cd pdd

# В уже открытом проекте начинай отсюда:
nvm install
nvm use
npm ci
npm run dev
```

Если nvm не установлен, установи Node.js 22 LTS самостоятельно и пропусти команды `nvm`. Проверь `node --version`: версия должна быть не ниже 22.12.0.

Открой адрес, который напечатает Vite, обычно [http://127.0.0.1:5173](http://127.0.0.1:5173). Для управления нужен компьютер с клавиатурой. Остановить сервер — `Ctrl+C` в его терминале. Сервер слушает только локальный компьютер.

Файлы `.env`, API-ключи, бэкенд и корпоративный VPN не нужны. `.npmrc` использует публичный npm registry; версии закреплены в `package-lock.json`. Зависимости устанавливай через npm, не создавай lock-файлы других менеджеров.

Для проверки production-сборки:

```sh
npm run build
npm run preview
```

Preview обычно открывается на [http://127.0.0.1:4173](http://127.0.0.1:4173); точный адрес смотри в терминале. Это локальный просмотр, не публикация сайта.

| Клавиши     | Действие                     |
| ----------- | ---------------------------- |
| W / ↑       | Разгон                       |
| S / ↓       | Торможение, затем задний ход |
| A, D / ←, → | Руль                         |
| Пробел      | Тормоз до полной остановки   |
| Q, E        | Поворотники                  |
| Esc         | Пауза / продолжение          |

## Что реализовано

Свободная поездка → нарушение → общий разбор причин → авторский вопрос или локальное объяснение → продолжение → журнал и повтор.

- STOP, городской лимит 60 км/ч и знак 30, запрещающий сигнал, четыре ошибки указателя поворота и помеха пешеходу.
- Общее время всех участников, геометрия пересечений и манёвров, независимые причины паузы и полный повтор состояния.
- Закреплённые материалы, миграция истории 0.1.0, отдельные попытки и пропуски, поездки без ошибок и итог завершения.
- «Знакомимся с городом»: ручной выбор пяти ситуаций, ориентиры на карте и подсказки; компактные кнопки в один ряд.
- «Правильных манёвров»: учёт завершённых ситуаций по пяти группам без повторного начисления за один эпизод.
- Увеличенный журнал с фильтрами и вертикальной прокруткой вместо страниц. Крупный текст, селекты с внутренними отступами и колонка типов одинаковой ширины; возврат из разбора сохраняет позицию списка и фокус.
- Просмотр истории без запуска поездки, длинные вопросы и иллюстрации доступны через переключатели без обрезки.
- Ограничение скорости всегда отображается в нижней панели во время поездки; отдельной настройки нет.
- Сохранение в IndexedDB с валидацией и очередью; при ошибке данные остаются в памяти, непрочитанная история не перезаписывается молча.

**По ТЗ 0.2.0-preview.1 официальные билеты не требуются.** Обязательны объяснение нарушения и ссылка на соответствующий пункт ПДД. В текущем интерфейсе остаются пять явно авторских вопросов как необязательное дополнение. Все девять причин и применимые нормы сверены по КонсультантПлюс 14.10.2026. Технические задачи текущей версии выполнены; перед итоговой приёмкой остаются пилот с учениками и исправления по его результатам. Актуальный остаток работ — в [ТЗ](TZ-PDD-MVP.md); [реестр материалов](docs/implementation/CONTENT.md) описывает текущий комплект, [результаты проверок](docs/implementation/ACCEPTANCE.md) приведены с датами их выполнения. Автомобильного потока, полного набора ПДД и мобильного управления нет.

Сохранение рассчитано на одну активную вкладку. Синхронизации между вкладками/устройствами и гарантированного запуска без сети пока нет. Шрифты поставляются локально вместе с приложением.

## Проверенная среда и состояние версии

Целевая среда — компьютер с клавиатурой, Chrome/Edge, окно от 1024×650 CSS px при 100%. Автоматические проверки выполнены на macOS arm64 в Chromium 156.0.8078.4; отдельные установки Chrome/Edge на Windows, Firefox и Safari не проверялись. Поездка с телефона не поддерживается.

Проверен настоящий масштаб браузера 125%, 150% и 200%. При доступной высоте до 600 CSS px появляется прокрутка, чтобы сохранить доступ к тексту и кнопкам. Основная матрица при 100% по-прежнему помещается в один экран.

14 октября прошли 136 проверок логики, 20 браузерных сценариев, линтеры и сборка. Журнал проверен на 1000 записях, сессия — на часе ускоренной симуляции. [Состояние задач](TZ-PDD-MVP.md#7-выполнение-задач-версии) зафиксировано в ТЗ; [пилот](docs/implementation/PILOT.md) ещё не проведён. Это локальная проверка без нового CI и публикации.

## Архитектура

```text
src/domain          модель мира, пять групп правил, манёвры, оценка ответа
src/use-cases       игровая сессия и порты, пауза, история, повтор
src/adapters        клавиатура, цикл, IndexedDB, локальные материалы
src/presentation    Phaser: город; React: интерфейс
src/content         карта, авторские вопросы и ссылки на ПДД
src/bootstrap       сборка зависимостей и освобождение ресурсов
tests/unit          отдельные правила и функции
tests/integration   взаимодействие модулей, сессия и хранилище
tests/e2e           браузерные сценарии
```

Домен не зависит от браузера, Phaser и React. Use-cases получают хранилище и контент через порты. Phaser рисует координаты доменной симуляции, а React получает подготовленные показатели поездки не чаще 10 раз в секунду при движении. Публичные снимки отделены от внутреннего состояния и защищены от записи типами и `Object.freeze`. Границы импортов закреплены ESLint.

Параметры текущего предпросмотра: 60 шагов/с, не более 6 догоняющих шагов; координаты в метрах, X вправо, Y вниз, угол в радианах от оси X по часовой стрелке. Машина 4.2 × 1.8 м. Остановка для STOP: скорость ≤ 0.03 м/с и передний бампер в пределах 3 м до линии. Это технические допуски для проверки прототипа, не дополнительные требования ПДД. Локальный замер на Apple M2 Pro приведён в матрице приёмки; на разных устройствах быстродействие ещё не подтверждено.

Стек сборки: Vite, npm и зафиксированный `package-lock.json`. Изображение города строится средствами Phaser; отдельные растровые ресурсы пока не нужны. Тесты — Vitest, fake-indexeddb и Playwright.

Все тесты находятся в `tests/`: модульные и интеграционные — `*.test.ts` (Vitest), браузерные — `*.spec.ts` (Playwright). В `src/` тестов нет. Проверки шага симуляции и учёта правильных манёвров относятся к интеграционным: они проверяют совместную работу движения, детекторов и прогресса. Сессия проверяется с хранилищем в памяти, адаптер IndexedDB — через fake-indexeddb.

## Качество кода и оформление

Правила кода, CSS и доступности — в [стайлгайде](docs/STYLEGUIDE.md), компоновка и визуальное поведение — в [правилах дизайна](docs/DESIGN.md). Настройки VS Code / Cursor лежат в `.vscode`: установи рекомендованные расширения, чтобы получать диагностику и исправления при сохранении.

| Команда                                     | Что делает                                                             |
| ------------------------------------------- | ---------------------------------------------------------------------- |
| `npm run check`                             | Типы + ESLint + Stylelint + Prettier check + unit/интеграционные тесты |
| `npm run lint`                              | Проверка TypeScript, React и CSS; предупреждения считаются ошибкой     |
| `npm run lint:code` / `npm run lint:styles` | Проверка только кода / CSS                                             |
| `npm run lint:fix`                          | Автоисправления линтеров                                               |
| `npm run format` / `npm run format:check`   | Форматирование / проверка без записи                                   |
| `npm run fix`                               | Автоисправления, затем форматирование                                  |
| `npm run typecheck`                         | Проверка типов                                                         |
| `npm test`                                  | Unit- и интеграционные тесты                                           |
| `npm run test:unit`                         | Только модульные тесты                                                 |
| `npm run test:integration`                  | Только интеграционные тесты                                            |
| `npm run test:e2e`                          | Браузерные сценарии Playwright                                         |

Перед завершением изменения:

```sh
npm run fix
npm run check
npm run build
npx playwright install chromium  # один раз для браузерных тестов
npm run test:e2e
```

Если автоисправление остановилось с ошибкой, исправь оставшиеся замечания вручную и повтори команду. `check` ничего не исправляет и не заменяет сборку или E2E.

Локально для текущей версии прошли 136 unit/интеграционных тестов и 20 сценариев Chromium. Проверяются пять групп правил, правильные манёвры, граничные случаи, повтор, пауза, раздельный учёт ответов и сбои хранилища. Браузерные тесты покрывают игровой цикл, сохранение после перезагрузки, потерю фокуса, справочник, компоновку и прокрутку журнала на 121 и 1000 записях, независимые основания причин и масштаб браузера до 200%. GitHub Actions запускает те же проверки, сборку и E2E при push и pull request.

На 9 октября 2026 года `npm audit` отмечает 8 high-записей в цепочке dev-зависимостей Stylelint из-за [уязвимости braces](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm). Для установленной цепочки аудит не предлагает совместимого исправления; предложенный аудитом откат на старый Stylelint не применён. `npm audit --omit=dev` проходит без замечаний. Это отдельная проверка зависимостей, не часть `npm run check`.

## Если запуск не получился

- **Слишком старая Node.js:** выполни `nvm install && nvm use`, затем `npm ci`.
- **Порт занят:** Vite напечатает другой адрес. Можно явно задать `npm run dev -- --port 5174`.
- **Playwright не находит Chromium:** выполни `npx playwright install chromium`; в Linux при отсутствии системных библиотек — `npx playwright install --with-deps chromium`.
- **Ошибка `npm ci` после изменения зависимостей:** разработчик обновляет `package-lock.json` командой `npm install` вместе с `package.json`. Не удаляй lock-файл как обычный способ запуска.
- **Не сохраняется история:** браузерное хранилище может быть недоступно. Игра сообщает об этом и продолжает в памяти. Не очищай данные браузера, если хочешь сохранить журнал.
