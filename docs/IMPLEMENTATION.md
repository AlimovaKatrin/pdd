# Техническое описание реализации · 0.1.0

Документ описывает код первой версии в [коммите a88ec22](https://github.com/AlimovaKatrin/pdd/commit/a88ec228138d8a26d22790d2fd3ccbe1ec20edd8). Требования к дальнейшим изменениям находятся в [AGENTS.md](../AGENTS.md), [DESIGN.md](DESIGN.md) и [STYLEGUIDE.md](STYLEGUIDE.md). Более широкая [архитектура v1.0](../ARCHITECTURE-WEB-v1.0.md) описывает и ещё не реализованные подсистемы.

## Запуск и зависимости

Один клиентский проект: TypeScript, React 19, Phaser 3, Vite 7 и IndexedDB. Требуется Node.js 22.12+; npm устанавливает версии по lock-файлу. Команды установки, разработки, сборки и проверки — в [README](../README.md#запуск).

Бэкенда, API, аккаунтов и переменных окружения нет. Шрифты Manrope поставляются локально, город рисуется средствами Phaser. Для production-сборки Vite создаёт `dist/`; настройка публичного хостинга в эту версию не входит.

## Поток данных

1. При инициализации сессия параллельно загружает историю и кандидатов вопросов. Ошибка одного источника не блокирует другой и доступ к поездке.
2. Клавиатура передаёт команды сессии. Runtime вызывает фиксированные шаги, только когда поездка начата и множество причин паузы пусто.
3. Доменный шаг возвращает новый мир и нарушения. Phaser читает мир для отрисовки, React получает опубликованные снимки: при движении каждые 6 шагов, при событиях сразу.
4. При нарушении сессия добавляет паузу, сбрасывает ввод, создаёт запись и контрольное состояние, запускает сохранение и публикует разбор. UI не вычисляет нарушение и не ждёт завершения IndexedDB.
5. Ответ создаётся отдельно от нарушения. Продолжение убирает разбор, повтор восстанавливает мир, а история не откатывается.

Реализация рассчитана на один тип правила и один проверяемый подъезд. Обобщённого объединения нескольких одновременных нарушений и ранжирования вопросов ещё нет; добавление правил требует отдельной реализации этих требований архитектуры.

## Время, координаты и проверка STOP

| Параметр      | Значение в коде                                                                                                                      |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Шаг симуляции | `1 / 60` секунды; не более 6 шагов за кадр runtime.                                                                                  |
| Координаты    | Метры; X вправо, Y вниз; угол от оси X по часовой стрелке, в радианах.                                                               |
| Карта         | 120 × 100 м; логическая отрисовка 960 × 800, 8 px/м до вписывания в контейнер.                                                       |
| Машина        | Доменная длина 4.2 м, ширина 1.8 м; увеличение спрайта `1.1` влияет только на изображение.                                           |
| Скорость      | От −3 до 12 м/с; UI показывает модуль скорости в км/ч. Это ограничение модели движения, а не проверка ПДД.                           |
| Остановка     | Скорость по модулю ≤ 0.03 м/с, передний бампер в пределах 1.5 м перед линией, подходящее направление и положение относительно линии. |

Допуски остановки — технические параметры прототипа, не нормативные требования. Обязательного времени стоянки перед STOP нет.

Пересечение проверяется по движению переднего бампера между предыдущим и новым состояниями, включая точку пересечения. После проезда эпизод становится `crossed`, чтобы не создавать нарушение каждый кадр. Новый подъезд перевзводит проверку при выходе из зоны эпизода; движение назад от линии сбрасывает ранее зачтённую остановку по условиям детектора.

## Паузы и жизненный цикл

Причины паузы: `manual`, `blur`, `incident`, `journal`. Мир идёт только при `started === true` и пустом наборе причин. Обычное продолжение снимает `manual` и `blur`, закрытие разбора — `incident`, закрытие журнала — `journal`. Одна операция не должна снимать несвязанную паузу.

`start()` создаёт новые ID поездки и попытки, начальный мир и очищает причины паузы, сохраняя историю. `finish()` останавливает поездку и открывает журнал. `retry()` и `returnToRoad()` сами не устанавливают `started`; если поездка ещё не началась, пользователь запускает её из стартовой карточки или через «К поездке» в журнале.

Контрольные состояния мира добавляются каждые 30 шагов; буфер хранит до 24 снимков. Для нарушения выбирается снимок примерно за 5 секунд до него либо самый ранний доступный. Сохраняется до 20 контрольных состояний нарушений. Всё это находится только в памяти; после перезагрузки остаётся история, но не точный повтор.

## Хранение и версии данных

IndexedDB: база `pdd-city`, версия 1, object store `history`, ключ `current`. Записывается целиком копия объекта `History` с `schemaVersion: 1`:

- `violations`: ID события, поездки и попытки, дата, объект дороги, эпизод, скорость, tick, версии карты и правил.
- `answers`: ID ответа, связь с нарушением, вопрос и версия контента, индекс варианта, правильность, признак помощи и дата.
- `revealed`: ID нарушений, для которых был показан разбор или получен ответ.

Версии текущих данных: карта `neighborhood-1`, правила `stop-prototype-1`, вопрос `demo-stop-line` с редакцией `demo-1`. Ответ не удаляет нарушение. Просмотр объяснения или нормативной ссылки до ответа устанавливает признак помощи. Пропуск определяется отсутствием ответа, отдельной записи пропуска нет.

Адаптер проверяет схему, обязательные поля, уникальность ID и связи записей. Сохранения идут последовательно через очередь. При ошибке чтения сессия не перезаписывает непрочитанную историю автоматически. При ошибке записи сообщает пользователю и оставляет текущие результаты в памяти. Очистка по явному подтверждению пользователя заменяет историю пустой и сохраняет её.

Миграций старых схем, многовкладочной синхронизации, серверного хранения, экспорта и фонового резервирования нет. История ограничена browser origin; адрес, порт и профиль браузера имеют значение.

## Проверки и развитие

Vitest проверяет доменную симуляцию и STOP, сценарии сессии и IndexedDB через fake-indexeddb. Playwright в Chromium проверяет пользовательский цикл, сохранение, управление и геометрию интерфейса. Результаты именно 0.1.0 и ссылка на CI находятся в [описании версии](VERSION-0.1.0.md#проверки-этой-версии).

Для нового правила нужны доменная проверка и тесты, данные дорожных объектов, соответствующий учебный материал с проверенным источником и интеграция в сессию. Не добавляй условие обнаружения нарушения в React или Phaser. Новая карта требует согласованного обновления данных и отрисовки: текущий рендерер содержит декоративные координаты этого квартала и не является универсальным редактором карт.
