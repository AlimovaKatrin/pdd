# Проверка длительной поездки

Протокол задачи #6, параметры зафиксированы до измерений 18 октября 2026 года.

Контрольное устройство: Apple M2 Pro, 32 ГБ памяти, macOS; локальный Chromium с окном 1280×720. Проверка проходит в отдельном браузере через тестовый вход Vite. Результат относится к этому окружению и не заменяет измерения на слабом компьютере.

Нагрузка: 10 минут реального времени, seed 301, шесть начальных машин и максимум восемь, 1000 записей в истории до старта. Водитель следует маршруту обычными клавишами. Разборы продолжаются; при столкновении выполняется безопасный возврат. Раз в минуту открывается длинный журнал, читается запись и проверяется потеря фокуса. После завершения удаляются React, Phaser, обработчики и игровой цикл.

Бюджеты: 95-й процентиль шага симуляции менее 8 мс; интервал между кадрами во время движения менее 34 мс для 95% последних измерений; рост удерживаемой JS-памяти после сборки мусора менее 20 МиБ; рост числа DOM-узлов менее 200 при одинаковом состоянии интерфейса; открытие журнала менее секунды. Это технические ориентиры предпросмотра на контрольном устройстве, а не обещание для любых устройств.

Измерение времени шага оборачивает настоящий вызов `GameSession.step` в тестовом входе. Отдельной физики нет. Для интервалов кадров используется `requestAnimationFrame`; это частота обновления, а не время работы GPU. Выборки ограничены последними 10 000 значениями. Память и узлы измеряются через Chrome DevTools Protocol. Итоговый JSON сохраняется в `/tmp/pdd-performance-result.json`.

Короткий отладочный запуск допускается через `PDD_PERF_SECONDS`, но не считается десятиминутной проверкой. Результаты полного запуска добавляются после его завершения.

## Исправления до итогового замера

Короткие диагностические прогоны выявили два источника удержания объектов при пересоздании интерфейса. Phaser 3.90 не снимал обработчик `visibilitychange`; его неиспользуемый ввод также оставлял обработчики на canvas в пуле. Снимок JS-памяти показал цепочку от пула canvas через InputManager к удалённому контейнеру карты.

Ввод Phaser отключён: клавиатурой владеет адаптер приложения. Для освобождения обработчиков видимости используется `patches/phaser+3.90.0.patch`, применяемый `patch-package` в `postinstall`. Версия Phaser закреплена точно; при обновлении зависимости патч нужно пересмотреть. Патч охватывает исходный модуль и обе используемые поставкой сборки. Правило Git для patch-файлов допускает обязательный пробел строк контекста; правила форматирования кода не ослаблены.

Отдельная диагностика пяти пересозданий: до исправлений число DOM-узлов росло примерно на 259 за пересоздание; после исправлений — 325 при первом показе, затем 345 без дальнейшего роста. Это короткая диагностика утечки, не итоговый десятиминутный результат.

Сам измеритель передаёт из браузера только необходимые признаки разбора, а не журнал из 1000 записей на каждом опросе. Базовый замер выполняется после одного прогревочного пересоздания интерфейса; сборка мусора вызывается дважды. Иначе диагностика измеряла бы собственную передачу больших объектов и первоначальное выделение ресурсов.

В диагностическом маршруте исправлены две точки, которые направляли водителя против потока. Второй диагностический запуск показал ограничение простого клавиатурного водителя: он не умеет самостоятельно разъезжаться при взаимном ожидании. Оба незавершённых запуска не считаются итоговым замером.

В итоговом сценарии водитель использует обычную кнопку безопасного возврата после 20 секунд остановки, сохраняя тот же мир, поток и историю. Возвраты записываются в отчёт. Требуется проехать не менее 1500 м за десять минут; телепортации в расстояние не входят. Это нагрузочный сценарий с ошибками и возвратами, а не доказательство безошибочной автономной езды. Обычный поток без вмешательства игрока проверяется отдельно в `city-traffic.test.ts`.

## Итог · 18 октября 2026 года

Полный запуск `npm run test:performance` прошёл за 600 секунд. Контрольное окружение: Mac14,9, Apple M2 Pro, 32 ГБ, macOS 26.6.2; Headless Chromium 156.0.8078.4, окно 1280×720, Vite development. Параллельных тяжёлых проверок во время замера не было. Это результат контрольного окружения, а не измерение production-сборки на всех устройствах.

| Показатель                                  | Результат | Бюджет    |
| ------------------------------------------- | --------- | --------- |
| Шаг симуляции, p95                          | 1,2 мс    | < 8 мс    |
| Интервал кадров, p95                        | 16,7 мс   | < 34 мс   |
| Рост удерживаемой JS-памяти после GC        | 3,06 МиБ  | < 20 МиБ  |
| Рост DOM-узлов в одинаковом состоянии паузы | 24        | < 200     |
| Самое долгое открытие журнала               | 211 мс    | < 1000 мс |

Пройдено 3213 м и 24 точки маршрута; телепортации не учитываются в расстоянии. В этом запуске автоматическому водителю не понадобились безопасные возвраты. Максимум — восемь машин, подтверждено движение вне камеры. В истории стало 1054 записи. Девять раз проверены журнал, потеря фокуса и пересоздание интерфейса. После удаления приложения нет canvas и активных сцен, новые шаги не выполняются. Необработанных ошибок страницы нет.

Полные измерения — в [performance.json](performance.json). p95 рассчитан по последним 10 000 значениям; максимумы и число измерений относятся ко всему запуску. Интервал RAF не является длительностью работы GPU.

Ошибки чтения, записи и несовместимость IndexedDB проверяются интеграционными тестами. Ограничение снимков и независимые паузы проверены в #19; отсутствие постоянных очередей обычного потока — в длительных доменных сценариях с несколькими seed. Эти проверки дополняют нагрузочный запуск, а не подменяются им.
